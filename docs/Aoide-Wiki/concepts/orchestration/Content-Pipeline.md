# Content Pipeline — Discover, Approve, Ingest, Query

**Status: designed, schema-real, exit-64 stub.** All five commands (`content
register/propose/approve/ingest/query`) parse, audit, and exit 64 today; the
live indexing/lint action described below is not yet implemented. See
[[Codebase]] for the walking-skeleton ladder.

## Pipeline stages

```
discover → propose → approve → ingest → lint → query
                                              ↓ (lint fail)
                                          quarantine
```

On lint failure, content is quarantined, not discarded. Drift re-lints and quarantines — it never poisons the live index.

## Folder contract

Every content source is a plain folder plus a metadata file:

```
<source-folder>/
└── .aoide/manifest.toml   # kind + conventions profile
```

The index points at content in place. It never copies files. The manifest declares what kind of content this folder holds and which conventions apply.

## The approve gate is non-negotiable

Discovery finds; the user admits. Silent adoption of arbitrary folders into an agentic index is an injection surface — an attacker who can place files on disk could otherwise inject instructions into the agent's context. The gate exists to break that path structurally.

## External sources

**Mneme:** read exclusively via Mneme's API. Raw filesystem access to a Mneme vault is not permitted. The vault declares its exports; Aoide decides what it admits through the same approve gate.

**Obsidian:** an integration dendrite is shipped and wired. It is `enable = false` by default — it is a toggle, independent of the Mneme integration.

## Dogfood: song design notes as pipeline content

`song/songbook/<song>/design/` — the per-song design memory generated by the self-ricing engine — are ordinary content-pipeline folders, pre-approved as system-owned. Aoide ingests its own design notes so the agent can query past rice reasoning like any other content domain. The pipeline and the rice engine are coupled by design here.
