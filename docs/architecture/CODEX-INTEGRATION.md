# Codex–Aoide integration roadmap

This is one proposal for completing Codex parity across Aoide's shell interfaces and the existing Lyra widgets. It records evidence and acceptance gates, not new User rulings. The user has requested integration, coordination with Claude through Aoide mail, command-flow criticism, and “Approve for me.” The orchestrator reports that a separate executor owns the conductor/terminals animation work. Those authorizations do not imply permission to bypass harness trust, conduct gates, or the deployment gate.

## Next execution brief: restore continuity before adding a profile

**Objective:** a shellbridge restart must not strand another live conducted session. Restore and prove Codex delivery, then record the actual submit behavior. This is the prerequisite for a reliable profile smoke test.

**Verified map:** `modules/nucleus/shellbridge.nix` assigns the shared `aoide` runtime directory to shellbridge. Conduct owns per-session sockets beneath that runtime root in `pkgs/aoide/crates/conduct/src/graph/conduct.rs`; its single cleanup authority is `reap.rs`. The orchestrator observed unlinked listeners and an absent Codex socket. Merely recreating a directory or pathname cannot reconnect an already-unlinked Unix listener.

**Proposed design:** retain the current runtime path and `0700` mode, and add `RuntimeDirectoryPreserve = "yes"` to shellbridge's service configuration through the permitted upstream/deployment route. Systemd documents that `yes` preserves the directory on stop; `restart` only covers restart operations and is insufficient for a separate stop/start transition. This is a proposed minimal repair, not a claim that it has landed. Conduct/reaper retain session cleanup ownership. Do not delete the shared root, restart all terminals, create fake socket paths, or add a second reaper. [Systemd's own manual source](https://raw.githubusercontent.com/systemd/systemd/main/man/systemd.exec.xml).

**Bounded ownership:** deployment author owns the applicable runtime-directory declaration and its same-commit module docs. A separate, serialized core phase may own `conduct.rs`/`reap.rs` only if code changes are necessary after the deployment fix. Neither lane owns Claude's mail files or the animation executor's song files. The orchestrator assigns exact paths from a fresh `git status --short`.

**Verification:** use an isolated runtime/stage/state/audit root for automated checks. In a controlled live session, record socket reachability and graph identity before/after the relevant service transition, send a harmless correlated token, and observe the recipient. Cover clean exit and kill/reap, including stale socket cleanup. Run only affected per-crate tests and serialize all cargo work with Claude. Independent review re-derives the result from the diff. Any deployment uses the existing user gate; no background rebuild.

**Done means:** the service transition preserves another session's control channel; Codex is reachable again; submit behavior is observed; and the result includes exact evidence plus any remaining deployment limitation. A proposed unit edit alone is not completion.

## Following execution brief: profile and basic metadata

After phase 0, reserve these writer paths explicitly: `protocol/src/agents.rs`; `conduct/src/commands/hooks.rs`; `conduct/src/graph/{send,session_store,resurrect}.rs`; and `conduct/src/reap.rs` only for capability handling. Paths are relative to `pkgs/aoide/crates/`. Coordinate `send.rs` with Claude before dispatch.

- Move event inventory, hook command/output policy, and configuration-root resolution into the harness profile. JSON format currently selects Claude behavior and omits `--agent`; adding a JSON Codex profile alone would dispatch its hooks as Claude. Codex's installed event enum lacks `Notification` and includes permission/interruption events.
- Add explicit Codex selection, the verified resume argv, and the measured submit byte. Keep permission keys unavailable. Make unsupported transcript/model-window capabilities representable instead of returning guessed values.
- Add a pure profile metadata extractor and one shared locked store update for direct hook telemetry. Preserve title ownership. Prefer native fields over unstable transcript parsing. Emit only the output shape permitted by each event; telemetry never returns a continuation/approval decision.
- Preserve caller context across aoided dispatch through a reviewed identity seam. Current hook routing forwards raw JSON, then registration derives ancestry/environment inside the handling process; this can describe aoided instead of the caller. Treat attribution and authenticated identity separately.
- Require native thread identity for Codex resurrection. Installed schemas distinguish `Thread.id` from tree-wide `Thread.sessionId`; old wrapper-only records need a taught refusal.
- Installer acceptance includes root override, repeated install, preservation of unrelated hooks, duplicate handling, uninstall, and installed-versus-trusted status. Do not mutate trust stores or add hook-trust bypass flags.

Use sanitized installed-version hook fixtures plus isolated `aoide-protocol`/`aoide-conduct` tests. Prove real start→send→turn→interrupt→end/kill→reap with aoided present and absent. Basic phase acceptance does not claim context meters, subagent parity, native queued delivery, or permission-widget actions.

Update protocol/conduct README/AGENTS in the same commit, integrate the Codex recipe into `docs/Aoide-Wiki/concepts/orchestration/Agent-Hooking.md` and `protocol/dev`, and correct stale deployment commentary in its authorized lane. Published wire changes require `CONTRACTS.md`; command additions/removals require the owning CLI golden. Review remains a different instance from execution.

## Evidence and unresolved risks

- **Local:** `codex --version`, `--help`, `resume --help`, `queue --help`, `app-server --help`, and generated `v2/{ThreadReadResponse,ThreadResumeParams,HookStartedNotification,HooksListResponse,ThreadTokenUsageUpdatedNotification}.json`. These prove syntax/schema, not a working live endpoint or active hooks. `ApprovalsReviewer` includes `auto_review`; model metadata explicitly is not per-turn execution telemetry.
- **Local code:** `protocol/src/agents.rs`, `conduct/src/commands/hooks.rs`, `conduct/src/graph/{send,session_store,resurrect,permit}.rs`, `conduct/src/reap.rs`, `modules/dendrites/openai.nix`, and `modules/nucleus/shellbridge.nix`. Re-read before dispatch because Claude is editing the shared tree.
- **Live/orchestrator:** proxy connection failed because no control socket exists; runtime cleanup unlinked live conduct listeners; the recent switch removed Codex's socket; submit-byte verification could not run. These are observed failures, not proof that any proposed fix has landed.
- **Official:** [Codex hooks](https://learn.chatgpt.com/docs/hooks), [app-server](https://learn.chatgpt.com/docs/app-server), and [configuration schema](https://learn.chatgpt.com/docs/config-schema.json). Hook trust/fields and unstable transcript guidance come from current documentation; validate activation against installed 0.153.4. Do not assume an event's presence means every tool path emits it.
- **Repository mail authority:** `docs/architecture/MAIL.md` keeps deposit, read, doorbell, and conduct tasking distinct. Its settled rules are existing project decisions; proposed identity and handshake acceptance above adds no new policy. Inspect the landed implementation and running binary before giving exact reader-binding commands.
- **Remaining risks:** shared-daemon versus thread lifetimes, lost caller identity through daemon routing, retry duplicates, migration of wrapper identities, provider/API availability, unknown context semantics, stale runtime binaries after a switch, and concurrent writer/cargo collisions. Each is assigned an acceptance gate above; none should be hidden by fallback to Claude defaults or optimistic widget labels.
